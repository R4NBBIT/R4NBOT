## ⚙️ 실행 방법

1. `requirements.txt`의 의존성을 설치합니다.
2. 프로젝트 루트에 `.env` 파일을 만들고 아래 내용을 채웁니다. (디스호스트를 쓰신다면 "간편 설정 → 환경변수(.env) 설정" 카드로 등록해도 동일하게 동작합니다.)

```
BOT_TOKEN=
EGG_ID=
LOSTARK_API_KEY=
```

| 변수 | 설명 |
|---|---|
| `BOT_TOKEN` | 디스코드 개발자 포털에서 발급받은 봇 토큰 |
| `EGG_ID` | 봇 소유자(계란) 디스코드 사용자 ID. `/레이드추가` 등 "계란 전용" 명령어와, `/메뉴추가`의 공통 메뉴 추가 권한 체크에 사용됩니다. 비워두면 계란 전용 명령어는 아무도 사용할 수 없습니다. |
| `LOSTARK_API_KEY` | 로스트아크 공식 오픈 API 키. 레이드 참가신청 시 캐릭터 레벨/직업 조회에 사용됩니다 (발급 페이지). 비워두면 참가신청/닉네임변경이 항상 실패합니다. |

디스코드 사용자 ID는 디스코드 앱에서 설정 → 고급 → 개발자 모드를 켠 뒤, 본인 프로필을 우클릭 → ID 복사로 확인할 수 있습니다.

3. `python bot.py`로 실행합니다.

```
discord.py==2.7.1
httpx>=0.27.0
aiohttp>=3.9.0
```

`httpx`는 레이드 참가신청 시 로스트아크 API 호출(`core/lostark_api.py`)에 사용됩니다.

## 🖥️ systemd로 등록하기 (VM에서 죽어도 자동 재시작)

VM(예: GCP `e2-micro`)처럼 직접 리눅스 서버에서 돌릴 때는, 봇 프로세스가 죽거나 서버가 재부팅돼도
자동으로 다시 떠있도록 `systemd` 서비스로 등록하는 걸 권장합니다. `deploy/r4nbot.service`에
템플릿이 있습니다.

1. 코드를 올려둘 경로(예: `/opt/r4nbot`)에 저장소를 클론하고, 그 안에 가상환경을 만들어 의존성을 설치합니다.
   ```bash
   sudo git clone https://github.com/R4NBBIT/R4NBOT.git /opt/r4nbot
   cd /opt/r4nbot
   python3 -m venv venv
   ./venv/bin/pip install -r requirements.txt
   ```
2. `/opt/r4nbot/.env`를 만들고 위 환경변수들을 채웁니다.
3. 봇 전용 시스템 사용자를 만들고(루트로 안 돌리는 게 안전해요), 그 경로의 소유자를 바꿔줍니다.
   ```bash
   sudo useradd --system --no-create-home r4nbot
   sudo chown -R r4nbot:r4nbot /opt/r4nbot
   ```
4. `deploy/r4nbot.service`를 `/etc/systemd/system/r4nbot.service`로 복사합니다. 경로(`/opt/r4nbot`)나
   사용자(`r4nbot`)를 다르게 썼다면 파일 안의 값도 맞게 수정해주세요.
   ```bash
   sudo cp deploy/r4nbot.service /etc/systemd/system/r4nbot.service
   ```
5. 서비스를 등록하고 바로 시작합니다.
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now r4nbot
   ```
6. 상태/로그 확인:
   ```bash
   sudo systemctl status r4nbot      # 현재 상태
   sudo journalctl -u r4nbot -f      # 실시간 로그 (Ctrl+C로 종료)
   ```
7. 코드를 업데이트한 뒤에는 `git pull` 후 재시작하면 됩니다. (아래 "push하면 자동으로 배포되게
   하기"를 설정해두면 이 단계는 수동으로 안 해도 됩니다.)
   ```bash
   cd /opt/r4nbot && sudo -u r4nbot git pull
   sudo systemctl restart r4nbot
   ```

이렇게 등록해두면 `Restart=on-failure`로 봇 프로세스가 죽어도 5초 뒤 자동으로 다시 뜨고,
`WantedBy=multi-user.target`로 VM이 재부팅돼도 봇이 자동으로 다시 시작됩니다. 다만 짧은 시간에
너무 자주 죽으면(5분 안에 10번) systemd가 재시작을 포기하고 멈추도록 안전장치가 걸려 있어요
(`StartLimitIntervalSec`/`StartLimitBurst`) — 이 경우엔 `journalctl -u r4nbot`로 원인을 먼저 확인하고
`sudo systemctl reset-failed r4nbot && sudo systemctl start r4nbot`으로 다시 시작하면 됩니다.

## 🔄 push하면 자동으로 배포되게 하기 (cron)

깃허브에 push할 때마다 수동으로 `git pull` + 재시작을 하지 않아도 되도록, VM에서 cron으로
주기적으로 "새 커밋 있으면 pull 받고 재시작"을 돌릴 수 있습니다. `deploy/auto_deploy.sh`가
그 스크립트입니다. VM이 깃허브로 나가서 확인만 하는 방식이라 포트를 따로 열 필요가 없어요.

1. 스크립트 안의 `REPO_DIR`(기본 `/opt/r4nbot`), `REPO_USER`(기본 `r4nbot`), `SERVICE_NAME`
   (기본 `r4nbot`)이 실제 환경과 다르면 맞게 수정합니다. (위 systemd 설정에서 쓴 값과 같으면
   손댈 필요 없음)
2. root의 crontab에 등록합니다. (systemd 서비스를 재시작하려면 root 권한이 필요해서, git/pip
   작업만 스크립트 안에서 `sudo -u r4nbot`로 내려서 실행함)
   ```bash
   sudo crontab -e
   ```
   아래 줄을 추가 (2분마다 확인, 변경 없으면 아무 일도 안 하고 조용히 끝남):
   ```
   */2 * * * * /opt/r4nbot/deploy/auto_deploy.sh >> /var/log/r4nbot-deploy.log 2>&1
   ```
3. 잘 등록됐는지 로그로 확인:
   ```bash
   tail -f /var/log/r4nbot-deploy.log
   ```
   이 레포에 새 커밋을 push하면, 최대 2분 안에 로그에 "새 커밋 발견 → pull 완료 → 재시작 완료"가
   찍히고 봇이 새 코드로 다시 뜹니다.

`requirements.txt`가 바뀐 커밋이면 재시작 전에 `pip install -r requirements.txt`도 자동으로 다시
실행해줍니다. 두 배포 스크립트가 동시에 겹쳐 돌지 않도록 락 파일로 막아두었습니다.

| `/레이드추가 <레이드> <난이도> <골드> <귀속골드> [입장레벨] [딜러정원] [서포터정원] [시작일] [종료일]` | 새 조합 추가 (총합 자동 계산, 정원 기본값 딜러3/서포터1, 이벤트 레이드면 시작일/종료일 입력) | 계란 전용 |

| `/레이드삭제 <레이드> <난이도>` | 조합 삭제 | 계란 전용 |

"싱글" 난이도는 혼자 도는 레이드라 `/클골`에는 나오지만 `/레이드` 모집 대상에서는 제외됩니다.

**시작일/종료일 (이벤트 레이드용)**: 기간이 있는 레이드(예: 3막/종막 익스트림)에만 설정하면 되고, 날짜는 `10/21`, `10월 21일`, `2026-10-21`처럼 입력해요. 시작일과 종료일은 둘 다 그날을 포함합니다.
- 레이드 일정 날짜가 시작일 이전이거나 종료일 이후면 `/레이드` 생성, 일정수정이 막혀요. (시작일 전에도 목록에는 보여서 미리 만들 수 있어요)
- 종료일이 지나면 `/레이드`, `/고정공격대생성`, `/레이드알림추가`, `/클골` 선택 목록에서 바로 사라지고, 길어도 1시간 안에 클리어 골드 데이터(`data/raid_gold.json`)에서 그 조합 자체가 자동으로 삭제돼요. 이미 올라간 모집 글은 그대로 유지되고, 고정공격대는 기간 밖 회차만 자동 게시를 건너뜁니다 (이건 기간 기록 자체는 계속 남겨두기 때문에 계속 정상 작동해요).
- 자동 삭제된 뒤에는 `/레이드수정`, `/레이드삭제`, `/클골`에서도 더 이상 안 보여요 — 같은 조합을 다시 쓰려면 `/레이드추가`로 새로 등록하면 됩니다. 기본값으로 3막/종막 익스트림 3종의 기간이 들어 있어요.

### 점심 메뉴 추천

메뉴는 두 종류로 나뉩니다: 모든 서버가 공유하는 **공통 메뉴**(`core/menu.txt`)와, 서버마다 따로 쌓이는 **서버 메뉴**(`data/guild_menus.json`). `/점메추`, `/메뉴판`은 "공통 메뉴 − 이 서버에서 숨긴 것 + 이 서버가 추가한 것"을 합친 목록을 기준으로 동작합니다. DM에서는 서버 개념이 없어서 공통 메뉴만 보여줍니다.

| 명령어 | 설명 | 권한 |
|---|---|---|
| `/점메추` | 메뉴 랜덤 추천 (리롤 버튼 포함) | 전체 |
| `/메뉴추가 <메뉴> [공통]` | 메뉴 추가. 기본(공통=아니오)은 이 서버에만 추가됨. 공통=예로 하면 모든 서버가 공유하는 공통 메뉴에 추가됨 | 전체 (공통=예는 계란 전용, DM 불가) |
| `/메뉴삭제 <메뉴>` | 메뉴 삭제. 이 서버에서 직접 추가한 메뉴면 그냥 삭제되고, 공통 메뉴면 실제로 지워지지 않고 이 서버에서만 안 보이게 됨 | 전체 (DM 불가) |
| `/메뉴판` | 이 서버에서 보이는 전체 메뉴 목록 조회 | 전체 |

| `/레이드채널 <채널>` | 레이드 모집 게시물을 올릴 포럼 채널 지정 (서버당 1개, 이미 지정돼 있으면 덮어씀) | 관리자 |
| `/레이드채널해제` | 레이드 채널 지정 해제 | 관리자 |
| `/레이드채널정보` | 현재 지정된 레이드 채널 확인 (채널이 삭제된 경우 자동으로 지정 해제) | 전체 |
| `/레이드 <제목>` | 날짜/시/분/레이드/난이도 모달 → 제출 후 "설명 작성하기" / "설명 없이 게시" 선택 → 지정된 포럼 채널에 게시물 생성 | 전체 |

레이드 선택지: `/클골`에 등록된 조합 외에 **"기타"**를 고를 수 있어요. "기타"는 난이도 선택이 필요 없고(더미 옵션이 기본 선택돼 있음), 정원은 16인(딜러12/서포터4)으로 고정되며 입장레벨 제한이 없어요. 레이드가 아닌 다른 컨텐츠 모집용이라 `/클골`에는 나오지 않습니다.

시간 검증: 이미 지난 날짜/시간이나 등록되지 않은 (레이드, 난이도) 조합은 제출이 막히고, 입력했던 값이 그대로 채워진 "다시 입력" 버튼이 떠요.

게시물이 생성되면 봇이 바로 첫 댓글로 공격대 생성자를 멘션해요. 멘션이 걸린 댓글이 "새 활동"으로 잡혀서, 서버 멤버들의 사이드바에 새 글이 자동으로 노출돼요 (댓글이 없으면 디스코드 특성상 아무도 안 열어보기 전까지 잘 안 보임). 이 (레이드, 난이도) 조합을 아래 `/레이드알림추가`로 구독해둔 사람이 있으면 같은 댓글에 같이 멘션됩니다.

#### 레이드 알림 구독

| 명령어 | 설명 | 권한 |
|---|---|---|
| `/레이드알림추가 <레이드> <난이도>` | 해당 (레이드, 난이도) 모집 게시물이 새로 올라올 때 멘션받도록 구독 | 전체 |
| `/레이드알림삭제 <레이드> <난이도>` | 구독 해제 | 전체 |
| `/레이드알림목록` | 내가 구독 중인 목록 확인 (나만 보임) | 전체 |

각자 본인 계정으로 원하는 조합만 구독하는 방식이라 관리자 설정 없이 개개인이 자유롭게 켜고 끌 수 있어요. "기타"는 레이드+난이도 조합이 없어서 구독 대상이 아니에요.

**게시물에 달리는 버튼:**

| 버튼 | 설명 | 권한 |
|---|---|---|
| 참가신청 | 캐릭터 닉네임 입력 → 로스트아크 API로 레벨/직업/전투력 조회 → 존재하지 않는 캐릭터거나 입장레벨 미달이면 거부 → 딜러/서포터 겸용 직업(도화가·바드·홀리나이트·발키리)만 역할 선택창이 뜨고 나머지는 자동 딜러 → 자리 있으면 즉시 등록, 없으면 대기열 등록. 한 사람당 캐릭터 1개만 신청 가능 | 전체 |
| 참가변경 | 이미 신청한 캐릭터의 닉네임만 변경 (역할·대기 순서는 유지) | 전체 |
| 참가취소 | 본인 신청 취소. 참가자였다면 대기열에서 같은 역할 1순위를 자동 승격 | 전체 |
| 대기열 명단 | 현재 대기열 확인 | 전체 |
| ⚙️ 관리 | 아래 참고 | 서버 관리자 또는 작성자 |

**⚙️ 관리 패널 세부 버튼**

| 버튼 | 설명 |
|---|---|
| 일정수정 | 날짜/시/분(+설명)만 재입력 (레이드/난이도/정원은 안 바뀜) |
| 제목수정 | 게시물 제목의 자유 텍스트 부분만 수정 |
| 삭제 | "정말로 삭제하시겠습니까?" 확인 후 실제 삭제 |
| 강제참여 | 서버 멤버 검색 또는 "용병"(디스코드 계정 없는 외부인) 추가. 캐릭터는 실제 조회를 거치며, 존재하지 않는 캐릭터면 강제참여라도 거부됨. 정원·중복 신청 체크도 동일하게 적용 |
| 강제변경 | 기존 참가자/대기열 중 하나를 골라 관리자가 대신 캐릭터를 변경 |
| 강제취소 | 기존 참가자/대기열 중 하나를 골라 관리자가 대신 취소 |

레이드 시작 10분 전에는 참가자 전원을 태그하는 알림이 게시물(스레드)에 자동으로 올라옵니다. 레이드 시작 30분 후에는 게시물이 삭제되지 않고 포스트 닫기 + 포스트 잠그기(archived + locked) 상태로 자동 마감됩니다 (기록은 남되 더 이상 조작 불가). 두 기능 모두 1분마다 확인하는 백그라운드 작업(`cleanup_loop`)으로 동작하며, 일정수정으로 시간을 바꾸면 알림 발송 여부가 초기화돼 새 시간 기준으로 다시 알림이 갑니다.

### 공지

| 명령어 | 설명 | 권한 |
|---|---|---|
| `/공지 [서버]` | 서버를 고르면(자동완성) 그 서버 하나로, 비우면 봇이 들어가 있는 모든 서버로 공지 전송. 명령어 실행 후 뜨는 입력창(모달)에 공지 내용을 입력 | 계란 전용 |

- 채널을 미리 지정할 필요가 없어요. 서버마다 시스템 메시지 채널을 우선 쓰고, 없거나 못 쓰면 봇이 글을 쓸 수 있는 가장 위쪽 채널로 자동으로 보내요.
- 계란이 그 서버에 들어가 있지 않아도, 봇만 그 서버에 있으면 보내져요.
- 공지 내용은 명령어 칸이 아니라 모달(입력창)에 적어서, 줄바꿈이 있는 긴 공지도 편하게 쓸 수 있어요.
- `@everyone`/역할/멘션은 막혀 있어서 공지 내용에 멘션이 섞여도 실제로 울리지 않아요.

### 건의사항

| 명령어 | 설명 | 권한 |
|---|---|---|
| `/건의사항` | 입력창(모달)이 떠서 건의사항을 적으면 계란에게 DM으로 전달 | 전체 |
| `/건의사항답변 <건의사항>` | 아직 처리 안 한 건의사항을 자동완성으로 골라서, 입력창(모달)에 답변을 적으면 원래 작성자에게 DM으로 전달 | 계란 전용 |
| `/건의사항완료처리 <건의사항>` | 답장 없이 건의사항을 처리 완료로 표시해서 목록에서 뺌 (중복 건의, 반영할 필요 없는 건의 등) | 계란 전용 |

- 입력한 내용은 작성자 본인만 볼 수 있어요(모달 특성상 다른 사람에게는 보이지 않음).
- 제출하면 계란에게 DM으로 바로 전달되고, 보낸 사람·서버·시각도 함께 표시돼요.
- DM이 전달되지 않는 경우(계란과 서버를 공유하지 않거나 DM이 막혀 있는 경우)에도 건의사항은 기록으로 남아요.
- 답변도 같은 방식이에요 — 원래 작성자가 봇과 서버를 공유하지 않거나 DM을 막아뒀으면 전달이 실패할 수 있고, 그 경우 계란에게 안내 메시지가 떠요.
- `/건의사항답변`과 `/건의사항완료처리`의 자동완성 목록은 둘 다 "아직 처리 안 한" 건의사항만 보여줘요 — 답변을 보냈거나 완료 처리한 건은 더 이상 안 보여요.
